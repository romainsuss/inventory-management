Data flow

  1. The user changes one of four shared filters (Time Period, Warehouse, Category, Order Status) in the filter bar. State lives in singleton refs in useFilters.js.
  2. A watch in the view fires and calls a method in api.js, which drops any filter set to all and sends the rest as query params.
  3. FastAPI routes the request, and apply_filters and filter_by_month narrow the in-memory lists loaded from JSON.
  4. Endpoints such as /api/dashboard/summary aggregate the result, for example inventory value, low-stock count and pending orders.
  5. Pydantic validates the response model and FastAPI returns JSON.
  6. The view stores raw data in refs, and computed properties derive chart series, totals and formatted values, so the UI updates reactively.

Gaps worth knowing

Missing endpoints. client/src/api.js calls /api/tasks (list, create, delete, toggle) and /api/purchase-orders (create, get by backlog item). I found no matching routes in server/main.py, although it defines a PurchaseOrder model and loads purchase_orders.json. The Tasks and purchase order features would fail against the current backend.

Hardcoded API URL and open CORS. The base URL is fixed to http://localhost:8001/api and CORS allows every origin. Both are fine for a local demo and should change before any shared deployment.
